# ADR-0006: 불변 이벤트 로그 / 이벤트 소싱 데이터 캡처

- 상태: 채택됨
- 날짜: 2026-08-05

## 맥락 (Context)

랭킹(보상)·상장폐지 정산은 **조작 내성 평가가**("랭킹 가격(Ranking Price)")를 필요로 하고,
그 공식은 미래에 **실거래 백테스팅(backtesting)**으로 정한다(설계 스펙 D8). 즉 지금 어떤
알고리즘도 확정하지 않되, **나중에 어떤 알고리즘에도 대응**하려면 원천 데이터를 완전·정확히
남겨야 한다. 배당·정산의 감사·멱등도 필요하다.

## 고려한 대안 (Considered Options)

- **가변 상태 + 주기적 스냅샷** — 현재 잔액·보유·호가창을 덮어쓰며 유지, 가끔 스냅샷.
  단순하지만 **과거를 정확히 복원 못 함**(덮어쓰면 사라짐) → 백테스팅 불가.
- **불변(append-only) 이벤트 로그 + 파생값(projection)** — 모든 주문·체결·취소·배당·입금을
  덧붙이기만 하는 로그로 남기고, 잔액·평균 매입가·호가창은 로그에서 재계산. ← 선택

## 결정 (Decision)

**원장(체결·배당·입금) + 주문 이벤트 로그를 불변 append-only로 적재**(진실의 출처).
잔액·평균 매입가(avgCost)·현재 호가창은 이 로그에서 재계산되는 **파생값(projection)**.
과거 시점의 호가창도 로그로 **재구성**한다(이벤트 소싱(event sourcing)).

## 근거 (Rationale)

- **어떤 랭킹/정산 공식에도 대응** — 과거를 손실 없이 복원해 백테스팅 가능.
- **감사·멱등·디버깅** — 모든 변화가 추적됨(취소·STP 자동 취소도 이벤트).
- **Ranking Price(D8)·상장폐지 정산가(D9)**를 "정지 전 window" 기준으로 계산 가능.
- ⚠️ **스코프 경계**: 이건 **데이터 캡처**일 뿐, 매칭 엔진을 이벤트소싱 비동기로 짓자는 게
  아니다(그건 [[0005-매칭-동시성-모델|ADR-0005]]의 번복 대안). 로그만 남기면 된다 — 스코프 크립 금지.

## 결과 (Consequences)

- **얻는 것**: 미래 알고리즘 대응, 감사·재구성, 조작 내성 지표(랭킹·정산)의 기반.
- **감수하는 비용**: 저장 증가(로그), projection 재계산 로직.
- **재검토/번복 조건**: 로그 규모가 문제되면 **스냅샷 + 로그 절단(compaction)** 도입. 주기적
  호가창 스냅샷은 그전에도 성능 체크포인트로 선택 가능.
