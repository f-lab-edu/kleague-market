# ADR-0004: 데이터 = api-sports 단일 소스 + ACL + 내부 id

- 상태: 채택됨
- 날짜: 2026-08-02

## 맥락 (Context)

K리그 선수·경기 데이터가 필요하다. 실제 응답 probe로 api-sports v3의 K리그(league 292)
커버리지를 확인했고, K리그 공식 데이터 포털(data.kleague.com)도 후보였다.
데이터 세부는 [[2026-07-29-kleague-market-design]] "데이터 현실" 참조.

## 고려한 대안 (Considered Options)

- **소스**: api-sports 단일 / K리그 공식 포털 크롤링 / 3자 aggregator(footystats 등).
- **식별자**: api-sports player id를 공개 API에 노출 / 내부 id 발행.

## 결정 (Decision)

**api-sports 단일 소스** + `kleague-client` **ACL** + **내부 id(PK)** 발행.
`Player` 테이블은 내부 `id`(PK)와 `api_sports_id`(매핑 컬럼, **미노출**)를 함께 둔다.

## 근거 (Rationale)

### 1) K리그 공식 포털은 배제 (법적 리스크)

포털 ToS: *"모든 기록·자료는 보도 목적을 제외하고는 연맹의 사전 허가 없이 복사·저장·배포·
판매할 수 없다."* → 트레이딩 앱에 저장·활용은 **명백한 약관 위반**. 크롤링은 DOM 변경·차단
등 유지보수 부담도 크다. api-sports는 플랜으로 **합법 사용**.

### 2) api-sports 커버리지 (probe로 확인한 사실)

- ✅ 전 경기: `fixtures`(스코어), `events`(골·어시·카드·교체), `lineups`, `standings`, `topscorers`(rating 포함, 상위만).
- ⚠️ `fixtures/players`(경기별 rating·minutes): **~35%만**(2024 FT 20경기 중 7). 커버리지
  플래그 `statistics_players=true`지만 실제 불완전.
- **교차검증**: 같은 무료키로 **PL 2023은 rating 7.5·90분 정상 반환**, K리그는 빈값 →
  플랜 문제가 아니라 **K리그 데이터 자체가 부분적**. (유료 결제로도 안 열릴 공산 큼)

### 3) 데이터 한계 방어

per-match rating이 ~35%뿐이라 배당을 그에 의존하지 않고 **events + 팀 결과**로 설계한다
(전 경기 가용). 즉 데이터 현실이 배당 알고리즘 선택을 규정했다(ADR-0002 원칙과 별개).

### 4) ACL + 내부 id로 이중 격리

- **스키마 격리(ADR-0001)**: api-sports DTO를 `kleague-client`에서 도메인 모델로 번역 →
  필드 변경·제공자 교체 시 수정 범위를 한 모듈로 국한.
- **식별자 격리**: 공개 API에 외부 id를 노출하면 제공자 교체 시 클라이언트가 보는 id가 전부
  뒤집힌다. 내부 id는 마이그레이션이 비싼 **클라이언트 대면 요소**를 보호(매핑 테이블은 싸다).

## 결과 (Consequences)

- **얻는 것**: 법적 안전, 스키마·식별자 이중 격리, 제공자 교체 용이, 데이터 불완전성 방어.
- **감수하는 비용**: api-sports 데이터 한계 수용, `api_sports_id` 매핑 유지.
- **재검토/번복 조건**: per-match 성적이 핵심이 되면 허가받은 K리그 포털 또는 타 제공자를
  어댑터로 추가(공개 id는 내부 id라 불변).
