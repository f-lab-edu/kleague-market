# kleague-market 설계 스펙

> 상태: **기획 확정(MVP).** 튜닝 상수(공급 N·시작 포인트·수수료율·배당 가중치 등)는 구현 시 캘리브레이션.
> 아키텍처 대안 결정은 별도 `adr/`로 분리 기록. 여기엔 제품·경제·게임 규칙. [[README]]·[[workflow]] 참조.

## 비전 (한 줄)

K리그 선수를 자산으로 사고파는 **가상 포인트 기반 판타지 주식 거래소**. 실제 경기 성적이 배당으로 반영됨.

## 데이터 현실 (api-sports v3, K리그 = league **292** = K League 1)

실제 응답 probe + 교차리그 검증으로 확정(설계는 이 현실에 맞춤):
- ✅ **옴**: `fixtures`(일정·스코어·상태), `fixtures/events`(골·어시·카드·교체), `fixtures/lineups`(선발), `standings`, `teams`, `leagues`, `players/topscorers`·`topassists`(rating 포함, **상위 선수만**), `players/squads`(로스터).
- ⚠️ **sparse**: `players?league&season`(시즌 집계) — 2023은 **일부만** 채워지고 다수 null, `tackles`/`saves` 거의 null.
- ⚠️ **부분(~35%)**: `fixtures/players`(경기별 rating·minutes)는 **경기마다 있기도/없기도**. 2024 FT 20경기 샘플 중 **7경기만** 데이터(results:2), 나머지 results:0. 있을 때는 **팀당 20명·rating·minutes·saves 정상**(예: rating 6.3, 90분). 커버리지 플래그 `statistics_players=true`지만 실제 불완전. (유료 결제가 historical 공백을 메울지 불확실 → 필요 시 라이브 2026으로 재확인. tackles는 채워진 경기에서도 종종 null.)
- **함의**: per-match rating·minutes가 **~65% 경기에 없어 배당을 그에 의존 불가** → **배당 = events + 팀 결과**(events/lineups/score는 전 경기 가용). **출전자 = 라인업+교체이벤트로 파생**(minutes 없어도 됨). 시즌 개인스탯 sparse → **base value = 계층형 floor**.
- 무료 플랜: 10req/분, 100req/일. ~2024 무료, 2026 유료.
- **대안(2차)**: 공공데이터포털(data.go.kr)엔 K리그 경기/선수 기록 없음(등록정보류만). 공식 상세는 `portal.kleague.com`(크롤링) 또는 타 제공자 — per-match 성적이 핵심이 되면 이 경로. MVP는 api-sports만.

## 확정된 결정

### D0. 거래 모델 → **P2P 호가창 + 매칭 엔진** (ADR 예정)
- 사용자 간 지정가 주문을 매칭. 가격은 체결로 **창발**.
- "시스템-상대(AMM)"는 채택 안 함 → 2차 **마켓메이커 봇**이 호가창의 한 참가자로 흡수(유동성·파산방지·성적→시세를 봇 하나로 해결).
- 원칙: **거래가 가격을 만들고, 성적은 배당을 만든다**(두 시스템 분리).

### D1. 주식 발행/공급 + base value
- 선수당 **고정 총발행량**, 전 선수 **균일 N주**(구체 N 미정).
- 상장 시 **시스템이 전량 시드**(base value에 매도호가) → 이후 순수 P2P 유통.
- **base value = 계층형 floor (2요소, 상장 시 1회 산정)**:
  - **① 포지션 baseline**(1차 요소) — 포지션별 기본가 테이블(Enum/Map, O(1)).
  - **② 팀 tier 배수** — 2023 순위 기반 2~3단계.
  - **③ 2023 개인 스탯(rating+골+어시)이 있으면 상향 반영**, 없으면 `포지션baseline × 팀tier`.
  - 전부 **튜닝 상수**. 근거: 시즌 개인스탯 sparse → 단일 flat floor는 **분배 왜곡**(시스템 시드 front-run). 계층형은 **분배 공정성**을 위함(P2P라 인플레 위험은 아님).
  - 이후 성적은 가격 직접 안 건드림(배당만).
- **초기 매수 상한**: **상시 per-user per-player 보유 상한(constant cap)** — `보유+주문 ≤ cap` O(1) 체크. front-run + 한 선수 매점 집중 동시 억제. 튜닝 상수. (시간 쿨타임은 선택적 추가)
- **2024 시즌 데이터로 라이브 테스트**(경기·배당 진행).

### D2. 포인트 경제
- 가입 시 **시작 포인트 지급(넉넉히)**, 구체 금액 미정.
- 소스: 배당(시스템 발행) + 시작 포인트 / 싱크: 시드 물량 매수 → **약인플레 게임경제로 의식적 허용**.
- **MVP엔 파산 방지 장치 없음(YAGNI).** "항상 되팔기" 보장은 2차 마켓메이커(bid 공급)로. 친구초대 포인트 2차.

### D3. 배당 규칙
- **기준시점**: **경기 킥오프 시점 보유자 스냅샷**에게 지급(정산 직전 매수→먹튀 방지). 거래는 계속 열림.
- **공식 = 범용 2성분 가산 모델** (포지션 분기 없음 — 전 선수 동일 로직으로 창발적 차등):
  - **팀 성분**: 승/무실점(클린시트)/실점 등 팀 결과 → **그 경기 출전자에게 1/n 분배**.
  - **개인 성분**: 골·어시·페널티(+자책골·레드 상쇄) → 기록한 선수에게.
  - **총 배당 floor at 0** (클로백 없음). 부정 스탯은 개인 성분에서 상쇄만.
  - 결과: 공격수는 개인 성분↑, 수비수는 팀 성분↑ — **하드코딩 아닌 수식에서 창발.**
  - rating 기반 폐기 이유: per-match rating이 ~35% 경기만 있어 **불안정**(데이터 현실 참조) → 전 경기 가용한 events+팀결과로.
  - 가중치는 **튜닝 상수**.
- **출전자 정의**(1/n 대상): **`fixtures/lineups` 선발(startXI) ∪ `fixtures/events` 교체 IN.** (벤치만 앉은 선수 제외. per-match `minutes` 미제공이라 그걸로 정의 불가.)
- **정수/소수 정책**: 포인트는 **정수 minor-unit 스케일**(예: 내부 ×100 정수)로 저장·연산, **float/double 금지**. 1/n 분배 = **정수 나눗셈 + 버림**, **나머지는 시스템 싱크로 회수**(총량 보존). 스케일로 작은 배당이 0으로 소멸하는 것 방지.
- **멱등**: **(경기, 선수) 단위 1회.** 배치 재실행 시 정산된 경기 스킵.
- **타이밍**: 경기 종료 감지 시 배치 정산. 배당 규모(base value 대비)도 튜닝 상수.

### D4. 주문 의미론 (구체 API 엔드포인트는 나중에 별도 결정)
- **동기/비동기**: 주문 제출은 **동기**(즉시 매칭 시도 후 결과 반환), 응답은 "체결됨"이 아니라 **"주문 접수됨 + 즉시 체결분"**. 지정가는 반대편 호가가 없으면 호가창에 남으므로. 잔량의 이후 체결은 비동기적 성격 → 조회로 확인.
- 지정가만(MVP) · **정수 주 단위** · expectedPrice = 한도가(매수 최대지불/매도 최소수취).
- **부분 체결** 허용 · **가격-시간 우선순위** 매칭.
- 생명주기: `OPEN → PARTIALLY_FILLED → FILLED / CANCELLED`. 취소 = 잔량 취소.
- 유효기간: MVP **GTC**(취소 전 유효), 만료(TTL) 나중.
- **에스크로**: 매수=`한도가×수량` 포인트 예약, 매도=`수량` 주식 예약. 미체결 잔량은 예약 유지→취소 시 반환, 체결 시 이전.
- 매칭 실행: MVP는 **요청 스레드 동기 매칭(선수별 직렬화)**. 큐 기반 비동기 엔진은 나중.
- ⏸ **구체 엔드포인트/요청·응답 스키마는 나중 API 스펙 단계에서.**

### D5. 인증 (MVP 포함, 단 개발 순서상 1순위는 아님 — 트레이딩부터)
- **클라이언트**: 웹 + **모바일**(비전상 필수). → 인증은 **헤더 Bearer 토큰**(쿠키 아님).
- **토큰 상태**: MVP는 **서버측(opaque) 토큰** — 무효화 쉬움·단순·모바일 호환. **무상태 JWT는 멀티서비스/수평확장 필요 시 전환**(ADR + 메커니즘 격리).
  - 근거: 모바일은 "쿠키 vs 헤더" 축만 뒤집음(→헤더). "서버측 vs 무상태" 축은 규모가 결정 → 아직 서버측. JWT의 무상태 이점은 지금 불필요하고 리프레시 회전·블랙리스트 비용만 발생.
  - 구현 후보: Spring Session 헤더 세션 리졸버 또는 단순 토큰 스토어.
- **비밀번호 BCrypt 해시**(평문 금지). 가입/로그인/로그아웃/내 정보.
- **메커니즘 격리**: 컨트롤러·서비스는 세션/토큰을 모르고 `CurrentUser`/`SecurityContext`에만 의존 → 전환 비용 최소.
- **보호 범위**: 주문·포트폴리오·거래내역 = 인증 필요. **시세/마켓 조회 = 비로그인 공개.**
- **sybil(다계정)**: 범위 밖(가상 포인트·낮은 스테이크). 경량 완화는 나중.
- 미룸: 소셜/OAuth, 이메일 인증, 비밀번호 재설정, 리프레시 토큰, 역할·권한 체계.

### D6. 선수 유니버스 / 데이터
- **거래 유니버스 = 2024 K League 1(league 292) 전체 로스터**(시뮬레이션 시즌 선수). "1부만" 자동 충족.
- 로스터 소스: `players?league=292&season=2024`(~35p) 또는 `players/squads`(팀별). 메타(포지션·팀·사진) 포함.
- base value용 2023 스탯: `players/topscorers`·`topassists` + `players`(있는 것만); 없으면 D1 계층형 floor.
- 경기결과·성적 수집(배당용): `fixtures`(종료 감지) + `events` + `lineups` → 2024 시즌 배치.
- **데이터 소스 = api-sports 단일**(합법 사용). K리그 공식 포털은 **ToS상 저장·활용 금지**(보도 목적 외 사전허가 필요)라 **배제**.
- **어댑터(Anti-Corruption Layer)**: `kleague-client` 모듈이 api-sports DTO → 도메인 모델(`SeasonStats`/`MatchPerformance` 포트) 변환 전담. 도메인·배당엔진·DB는 api-sports를 **모름** → 제공자 교체 시 이 모듈만 수정. (= 모듈 ADR "kleague-client 분리 근거"의 구체화)

### D7. 수수료 / 스팸 방어 / 자전거래
- **거래 수수료**: **소액 명목 수수료(예 0.2%, 튜닝 상수)** — 체결(fill) 시 부과 → **포인트 싱크**로 배당 인플레 완화. 부분체결 반올림/버림은 D3 정수 minor-unit 정책 따름.
- **스팸/DoS 방어 = 레이트리밋(별개 문제, 상시 필수)**: 체결 수수료는 **미체결 주문 스팸을 못 막음**(체결 안 되면 수수료 0) → **유저당 주문 생성/취소 rate limit** 필수. 수수료 유무와 무관.
- **자전거래 = STP(Self-Trade Prevention)**: 단순 "매칭 스킵"은 **크로스드 오더북**(bid≥ask 잔존)을 유발하므로 금지. MVP는 **Cancel Taker** — 자기 호가와 체결될 상황이면 **taker 잔량 취소·예약 반환**(타 유저 호가엔 먼저 체결). 오더북 오염 없음.

### D8. 랭킹 / 포트폴리오 가치
- **포트폴리오 가치 = MVP 포함**: `현금 + Σ(보유수량 × 최근체결가; 미거래 선수는 base value 폴백)`. "지시적 평가값, 실현가 보장 아님" 명시.
- **랭킹(리더보드) = 2차**: 핵심 루프 아님(YAGNI) + 무결성이 조작 방어(마켓메이커·다계정)에 의존. 포폴가치가 MVP에 있어 나중에 얹기 쉬움.

## MVP 기능 목록

- **인증**(D5): 회원가입·로그인·로그아웃·내 정보. 헤더 Bearer(서버측 토큰), BCrypt 해시, `CurrentUser` 추상. 보호: 주문·포폴·내역 / 공개: 시세·마켓.
- **선수·마켓**(D1·D6): 2024 K리그1 전체 로스터 상장(선수당 고정 N주). base value = 계층형 floor(포지션 × 팀tier, 2023 스탯 있으면 상향). 시스템 전량 시드. 마켓 목록·시세 조회(공개).
- **거래/매칭**(D0·D4·D7): 지정가 주문 생성(동기, 접수+즉시체결분)·취소, 부분체결, 가격-시간 우선순위, 에스크로 예약/원자적 정산, 선수별 직렬화, STP(Cancel Taker), 소액 수수료, 유저당 주문 rate limit, 상시 per-user per-player 보유 상한.
- **포트폴리오/내역**: 보유 조회, 포폴가치(D8), 체결 내역.
- **배당 파이프라인**(D3): 2024 경기 종료 감지 배치 → events+팀결과 **2성분 가산 배당**. 킥오프 스냅샷 보유자, 출전자=라인업+교체, floor 0, (경기,선수) 멱등, 정수 minor-unit.
- **데이터 수집**(D6): `kleague-client` 어댑터가 api-sports → 도메인 모델(로스터·경기·events·lineups).
- **경제**(D2): 가입 시작 포인트, 파산방지 없음.

**구현 순서 힌트**: 트레이딩 도메인부터(인증은 1순위 아님). 계약 우선 — API 스펙 → API 스펙 기반 통합테스트(컨트롤러+DTO 더미, 서비스 없이) → 유닛 → DB → 실로직.

## API 스펙
⏸ **별도 작성 예정** — 실제 api-sports 응답 형태를 참조해 재작성(엔드포인트·요청/응답 스키마). 위 MVP 기능이 계약 범위.
