# docs

`kleague-market`의 프로젝트 위키. 이 `docs/` 폴더를 Obsidian 보관함으로 연다.
코드와 같은 git 리포에 있으므로 같은 PR에서 함께 수정·리뷰되고, 코드와 어긋나지 않는다.

## 세 기억 시스템의 경계

| 시스템 | 무엇 | 넣는 것 | 넣지 말 것 |
|--------|------|---------|-----------|
| **이 docs/ (Obsidian)** | Claude가 쓰는 정제된 위키 | 아키텍처, 설계 결정(ADR), 마일스톤 | 작업 일지, 이슈 |
| **Claude-Mem** | 자동 이벤트 로그 | 세션별 작업 기록 (자동) | 통독용 문서 |
| **GitHub** | 범위 계약·트래킹 | 이슈, 진행 상태, **범위 계약·Design Freeze**(그 기능에 한정된 결정·불변식·캘리브레이션) | **장기 아키텍처 서술**(→ `adr/`) |
| **Notion** | 사용자 본인의 이해 | 사용자가 자기 말로 정리 | 아키텍처의 진실의 출처 |

- 아키텍처의 **진실의 출처는 이 docs/ 하나**다. Notion은 여기서 파생된 이해.
- 이슈는 GitHub, 여기선 링크만 참조. 작업 일지는 Claude-Mem이 자동 기록.

## 작성 규칙

- 노트는 Markdown. 각 노트는 `# 제목` 하나로 시작. 파일명이 곧 노트명.
- 노트 간 연결은 `[[노트 이름]]` 위키 링크.
- 새 개념은 본문에 `[[새 노트]]`로 먼저 연결해 두고, 필요할 때 실제 파일 생성.
- 기능 완료의 정의(DoD)에 **"관련 docs 갱신"**을 포함한다. 안 그러면 위키가 썩는다.

## 작업 방식

- `[[workflow]]` — skill 사용 지도 + 한 기능 사이클. 작업 시작 전 이걸 따른다.

## 구조 (기획 진행하며 채운다)

- `[[architecture]]` — 시스템 아키텍처 (C4: Context → Container → Component)
- `adr/` — Architecture Decision Records. `NNNN-제목.md`, 불변, 맥락/결정/결과
- `[[milestones]]` — 이정표 (GitHub Milestones와 연결)
